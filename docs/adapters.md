# 接入自己的文稿

在文稿根目录放一份 `draftpair.json` 就可以指定阅读顺序、文件格式和项目自己的预览脚本。候选稿保留原文件的格式，批注保存文件路径、版本、预览块与原文行号。作者确认合并时，三方比较直接使用原始文本。

## 最小清单

```json
{
  "version": 1,
  "documents": [
    "序章.md",
    {"path": "chapters/market.tex", "title": "午后的菜市场"},
    {"path": "notes/街访记录.txt", "title": "采访手记"}
  ]
}
```

- `documents` 逐一登记项目内实际存在的 UTF-8 文本。数组顺序就是目录和连续全文的顺序。用相对路径和正斜杠，带空格或中文的文件名可以直接写。
- `title` 可省略。Markdown 和 LaTeX 会先尝试提取标题，其他格式默认用文件名。
- `format` 可写在文档条目中，也可写在清单顶层作为全书默认值。没有指定时，`.md`、`.markdown`、`.mdown`、`.qmd` 使用 `markdown`，`.tex`、`.ltx` 使用 `latex`，其他扩展名使用 `text`。已有 Quarto book 直接沿用原来的 `_quarto.yml`，同目录存在新清单时优先使用清单。
- `build` 可选。已有构建流程可写成 `{"check":["make","lint"],"render":["make","book"],"artifact":"out/书稿.pdf"}`。命令在文稿根目录运行，每一项参数占一个数组元素。可省略不使用的步骤，登记产物时一并登记产生它的 `render` 命令。

**保留 Quarto 原生预览，自定构建。** 已有 Quarto book 若通过 `quarto render` 直接生成 `out/book.pdf`，可以在书稿根目录放下列清单。工作台按 `_quarto.yml` 的顺序载入章节、引用和图表，合并时采用清单里的命令。请把 `artifact` 写成项目实际生成的文件。

```json
{
  "version": 1,
  "reader": "quarto",
  "build": {"render": ["quarto", "render"], "artifact": "out/book.pdf"}
}
```

## 预览如何对应原文

Markdown 使用 CommonMark，并支持表格和删除线。标题、列表、代码块、段落和表格保留各自的源行范围。图片路径相对于所在文档，也可以用以 `/` 开头的项目根相对路径。可在 HTTP 页面查看的本地图片随候选版本冻结。远程和缺失的图片以替代文字呈现。

LaTeX 按文件进行审阅。把 `\input` 或 `\include` 引用的正文片段分别列进清单，按成稿顺序排列。用本机 Pandoc 或 Quarto 捆绑的 Pandoc 预览章节、强调、公式、插图和表格。宏包、前导区和未能转换的命令可直接圈选源码。缺少 Pandoc 时，仍可浏览标题、按段批注源码、发布候选稿，最终排版交由原项目的构建命令完成。

`text` 按空行分段，保留段内换行，适合手记、台词草案，也可以作为一种新文本格式的初次接入方式。

## 为一种格式写预览适配器

例如一份排练稿把场景写作 `@ 电车站`，对白写作 `小安 | 明天还是这个点吗？`。下面的清单将 `.scene` 文件交给项目的 Python 脚本。可将仓库里的 [对白格式读入示例](adapters/dialogue.py) 复制为 `tools/dialogue.py`。

```json
{
  "version": 1,
  "documents": [
    {"path": "终点站.scene", "title": "终点站", "format": "dialogue"}
  ],
  "adapters": {"dialogue": "tools/dialogue.py"}
}
```

**输入。** 工具用自身的 Python 解释器执行脚本，工作目录为文稿根目录。标准输入是一份 UTF-8 JSON。每次转换以传入的 `source` 为准，其中可能是正式正文，也可能是历史稿或尚待作者确认的候选稿。

```json
{"version":1,"path":"终点站.scene","source":"@ 电车站\n\n小安 | 明天还是这个点吗？\n"}
```

**输出。** 标准输出写一份 UTF-8 JSON。每一块提供 `start`、`end` 和 Markdown 预览。源行号从 1 开始，两端均包含。区块按顺序排列并互不重叠。让每个可独立批注的段落或对象各占一块，直接保留原文中实际出现的文字。适配器未覆盖的非空源行会作为源码显示。

```json
{
  "version": 1,
  "blocks": [
    {"start":1,"end":1,"markdown":"## 电车站"},
    {"start":3,"end":3,"markdown":"**小安**　明天还是这个点吗？"}
  ]
}
```

脚本只需读取输入和生成预览。图片可在 Markdown 中引用，数字、日期、专名和符号应以源稿为准。诊断信息写入标准错误，失败时以非零状态退出。适配器会作为本地程序运行，清单中应登记作者或协作 agent 核对过的脚本。

## 接好后怎么验证

先在临时副本选一个段落保存意见、提交并按生成的交接命令发布候选。核对原句的文件及行号、候选的左右对照，以及正式文件在发布候选前后的内容。再试一份包含图片或公式的文件。对于新适配器，还应改动一行正文并检查预览，确认脚本读取了传入的那一稿。
